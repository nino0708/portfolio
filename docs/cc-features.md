## 1. Superpowers（プラグイン）

ベテランエンジニアの思考法・ワークフローをスキル群として詰めたプラグイン。動画では9つの筆頭に置かれ「入れるだけでアウトプットが変わる／絶対に入れた方がいい」と評価。特に **brainstorming スキル**（要件を詰めるための質問を投げ返してくる壁打ち役）が推し。開発に限らず、スキル設計・企画のブレストにも使える。

- 使いどころ: 実装前の要件詰め、計画・テスト・レビューの型を借りたいとき
- **この環境での状態: 導入済み**（2026-08-06 / v6.2.0 / scope=user）
  - 入手元: 公式マーケットプレイス `anthropics/claude-plugins-official` から SHA 固定で `github.com/obra/superpowers`（作者 Jesse Vincent・MIT）
  - 再インストール: `claude plugin install superpowers@claude-plugins-official`
  - 実体: `~/.claude/plugins/cache/claude-plugins-official/superpowers/6.2.0/`
- **収録スキル14本**（`Skill` ツールで `superpowers:<名前>` として呼ぶ）

  | スキル | 使うタイミング |
  |---|---|
  | `brainstorming` | 機能追加・新規作成の**前**に要件を詰める（動画の推し） |
  | `writing-plans` | 仕様が固まった多段タスクを、コードに触る前に計画化 |
  | `executing-plans` | 書いた計画を別セッションでレビュー関門付きで実行 |
  | `subagent-driven-development` | 同一セッション内で独立タスクをサブエージェントに配る |
  | `dispatching-parallel-agents` | 依存関係のない2件以上を並列化 |
  | `test-driven-development` | 実装コードを書く前に red/green |
  | `systematic-debugging` | バグ・テスト失敗時、修正案を出す前に原因を体系的に切る |
  | `requesting-code-review` / `receiving-code-review` | レビュー依頼と、受けた指摘の吟味 |
  | `verification-before-completion` | 「完了」「直った」と言う前に検証を強制 |

## 3. オートモード（`auto`）

権限モードの選択。動画の主張は **「権限をバイパス」から乗り換えろ**。バイパスは全許可なので、フォルダ全削除のような危険なコマンドも素通りする。オートモードは別の分類器モデルが実行前にアクションを審査し、安全なものは黙って通し、エスカレートするものだけ人間に返す。

- 使いどころ: 長時間タスク、許可待ちが頻発してテンポが悪いとき
- 危険度の並び: `plan` < `acceptEdits` < **`auto`** < `bypassPermissions`（最も危険）
- 裏取り: `公式ドキュメント確認済み` → 公式ドキュメント（https://code.claude.com/docs）
  - **v2.1.83 以降が必要**（動画の「2.1.32」は字幕の聞き取り違い。公式記載を採用）
  - リサーチプレビュー。**プロンプトを消すだけで安全性を保証しない**。機密操作のレビュー代わりにはしない
  - デフォルト化は**ユーザー設定**の `defaultMode: "auto"`。プロジェクト設定・ローカル設定の `defaultMode: "auto"` は無視される
  - Remote Control セッションと web のクラウドセッションでは `auto` は使えない

## 4. MCP

外部サービス接続の規格（**Model Context Protocol**。動画中の「マルチコンテキストプロトコル」は誤り）。Gmail・Googleカレンダー・Slack・Notion などに手足を伸ばせる。

動画で唯一**批判込み**で紹介された項目。「Gmailの下書きだけ作りたいのに、MCPを入れると読み取り・送信・ラベル付けまで全ツール定義が読み込まれてコンテキストを無駄に食う」。そのため **上級者はMCPを避け、CLI／コード直書きで必要な機能だけ持たせる**。

- 判断指針: **常時使う広範な連携はMCP、単機能はCLIスクリプト**。`tools/youtube/yt.py` はまさに後者の実例
- **この環境での状態: 運用中**（`.mcp.json` の google-design ほか、claude.ai コネクタ経由で Gmail/Drive/Calendar/Notion）
- 裏取り: `公式ドキュメントあり`。コンテキスト消費の考え方は 公式ドキュメント（https://code.claude.com/docs）

## 6. エージェントチームズ

セキュリティ担当・パフォーマンス担当・テスト担当・デザイン担当…といったチームを編成させる機能。プレビュー版。

- **サブエージェントとの違い**: チームメイトが**独立コンテキストを持ち、相互にやり取りする**。サブエージェントはメイン↔サブの往復のみで、メイト同士は会話しない
- 使いどころ: 複数観点で並走させたいとき（開発とデザインを同時に走らせる等）
- 起動方法: 「チームを編成して」のように自然言語で頼む。設定JSONの実験フラグが要るとの言及あり
- **この環境での状態: 未使用**
- 裏取り: `動画のみ`。ローカルの公式ドキュメントには記載なし。フラグ名・バージョン要件（動画は「2.1.32以降」）は**要確認**
