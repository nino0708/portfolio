# Tempus拡張: 検証ログ機能 設計（合意済み・2026-09-04）

## 背景・目的

二瀬樹は「仮説を立てて検証し、少しでも前に進んでいる実感」を得ることに強いモチベーションを感じる性格（[[user_core_motivation]]参照）。AWS運用保守の定型業務では改善のない反復に思考が止まる感覚があり、逆に自己啓発的な検証行為には明日への前向きさを感じる。

目標: **1日に大小問わず100個の検証を行う**ことを継続し、その蓄積から自分自身の法則・強み・傾向をまとめた「自分取扱説明書」を育てていく。

Tempusは既に本番稼働中のタスク管理PWA（Supabase + Cloudflare Workers）であり、本機能はその拡張として実装する。ただし既存のタスクプール（`tasks`テーブル）とは完全に分離する。

## 決定事項

| 項目 | 決定 |
|---|---|
| 位置づけ | Tempusの拡張機能。既存タスクプールとは別管理 |
| データ保存先 | Tempusと同じSupabaseプロジェクトに新テーブル `verifications` |
| 1件の構成 | 仮説/やること・結果と気づき・次のアクション・カテゴリ(自由入力)・日時 |
| UI | Tempusに新タブ「検証」を追加。クイック入力＋一覧＋当日カウンター(37/100形式) |
| カウンター | 当日件数のみ表示。連続達成日数(ストリーク)は出さない(プレッシャー回避) |
| 自分取扱説明書の育成 | 週次のクラウドルーティンで自動化。直近1週間の`verifications`を読み、パターン・法則を抽出してDrive上の**1つの固定ファイル**を上書き更新(スナップショット積み上げ方式ではない) |
| 保存場所 | Google Drive、ファイル名固定(例: `[自分取扱説明書].md`)。バージョン履歴はDriveのファイル履歴機能に委ねる |
| 既存ルールとの違い | Friday/Built Japanの「日付ごとに積む」命名規則(`[資料名][年][月日].md`)はここでは適用しない。育っていく1つのドキュメントという性質のため意図的に例外とする |

## データ構造

新規Supabaseマイグレーション `verifications` テーブル:

- `id` (uuid, PK)
- `owner_id` (uuid, 既存の`tasks`同様の所有者カラムに合わせる)
- `created_at` (timestamptz, default now())
- `hypothesis` (text, 必須) — 仮説/やること
- `result` (text, nullable) — 結果・気づき。検証直後は空でもよく、後から追記できる
- `next_action` (text, nullable) — 次のアクション
- `category` (text, nullable) — 自由入力（例: 自分軸/仕事軸/技術軸、決め打ちしない）

RLSは既存`tasks`テーブルと同様の所有者ベースポリシーを適用する。既存の`tasks`/`clips`とは外部キー関係を持たない完全独立テーブル。

## UI設計（Tempusフロント）

- 新規タブ「検証」を追加（既存の起票3口・タイムラインとは別画面）
- クイック入力フォーム: 仮説(必須) → 結果(任意、後から編集可) → 次のアクション(任意) → カテゴリ(任意)
- 一覧: 新しい順。カテゴリでの簡易フィルタは実装コストが低ければ入れる（必須ではない）
- 当日カウンター: 「37/100」のように当日作成件数を表示するのみ

既存コンポーネント(`CaptureBar`等)は流用せず、独立したタブ・コンポーネントとして実装する（案Aで合意）。

## 週次自動化（自分取扱説明書の育成）

- 新規クラウドルーティンを1本追加（Fridayの他ルーティンと同じ仕組み、週1回起動）
- 処理: 直近1週間分の`verifications`をSupabaseから読み取り → 繰り返し現れるパターン・強み・法則をLLMが抽出 → Google Drive上の固定ファイルを書き換え
- 既存の日次ブリーフィング統合ファイルへの反映は必須要件としない（将来の任意拡張）

## 実装範囲（v1）

1. Supabaseマイグレーション追加（`verifications`テーブル + RLS）
2. Tempusフロントに新タブ・入力フォーム・一覧・当日カウンターを追加
3. 新規クラウドルーティン1本（週次、Supabase読み取り + Drive書き込み）

## v1に含まないもの

- ストリーク表示
- カテゴリのプリセット化
- 自分取扱説明書のスナップショット履歴（Drive標準機能に委ねる）
- 日次ブリーフィングへの自動反映
