# drive-up — Drive アップロード／命名是正

Driveに上げる資料の名前を、決められた命名規則に必ず揃えるスキル。
アップロードとリネームはどちらも取り消しにくい操作なので、**実行前に必ず確認を取る**。

## 命名規則（これが唯一の正）

```
[資料名][年][月日].拡張子
```

例:
```
[月刊AWS_9月号][2026][0815].xlsx
[Friday商事_SNS戦略][2026][0815].md
```

守ること:
- 角括弧はリテラル。3ブロックを隙間なく連結し、末尾に拡張子を付ける
- **資料名に `_最新` は入れない**（本人が明示的に不要と指示）
- 年は4桁、月日は4桁ゼロ埋め（`0815`。`815` や `08-15` は不可）
- 同一日に複数ある場合は作成順に `_2` `_3` の枝番 → `[資料名][2026][0712]_2.md`

**日付は必ずJSTで取る。** Drive APIが返す `createdTime` はUTCなので、
そのまま使うと深夜生成分が1日ずれる（クラウドルーティンは朝7:00 JST＝UTC 22時台に動くため全件ずれる）。

```bash
TZ=Asia/Tokyo date +%Y      # → 2026
TZ=Asia/Tokyo date +%m%d    # → 0815
```

## 使い方

```
/drive-up <ファイルパス> [保存先フォルダ名]   # アップロード
/drive-up --fix <フォルダ名 or 検索語>        # 既存ファイルの命名是正
```

## モード1: アップロード

`$ARGUMENTS` の先頭が `--fix` でなければこちら。

### Step 1: 名前を組み立てる

1. ファイルパスの basename から**拡張子を除いた部分**を資料名にする
   - `~/Desktop/月刊AWS_9月号.xlsx` → 資料名 `月刊AWS_9月号`、拡張子 `xlsx`
2. `TZ=Asia/Tokyo date +%Y` と `+%m%d` で**実行日のJST**を取る
3. `[資料名][年][月日].拡張子` を組む

ファイルが実在するか `Read` か `ls` で先に確認する。無いパスを渡されたまま進めない。

### Step 2: 保存先フォルダを決める

`mcp__claude_ai_Google_Drive__search_files` で
`mimeType = 'application/vnd.google-apps.folder' and title contains '<フォルダ名>'` を検索し、
`fileId` を確定させる。

- 引数でフォルダ名が指定されていなければ、**どこに置くか AskUserQuestion で聞く**
- **マイドライブ直下（`parentId` 未指定）には置かない。** 過去に直下と
  フォルダ配下にファイルが散らばって整理しづらくなった実績がある
- 候補が複数ヒットしたら一覧を出して選ばせる

### Step 3: 同名衝突を確認

`search_files` で `parentId = '<フォルダID>' and title contains '<資料名>'` を検索し、
同じ `[年][月日]` のファイルが既にあれば `_2`（既に `_2` があれば `_3`）を付ける。

### Step 4: アップロード内容を提示して確認を取る

実行前に必ずこの表を出す:

| 項目 | 値 |
|---|---|
| ローカルファイル | `<パス>` |
| Drive上の名前 | `[資料名][2026][0815].xlsx` |
| 保存先フォルダ | `<フォルダ名>` |
| 変換後の形式 | スプレッドシート / Googleドキュメント / … |

「これでアップロードしていい？」と聞き、**OKが出るまで実行しない**。

### Step 5: アップロード

`mcp__claude_ai_Google_Drive__create_file` を使う。

- `title`: Step 1で組んだ名前
- `parentId`: Step 2で確定したフォルダID
- `contentMimeType`: 中身の実際のMIMEタイプ（**内容を渡すときは必須**）
- テキスト（`.md` `.txt` `.csv` 等）は `textContent` に UTF-8 のまま渡す
- バイナリ（`.xlsx` `.docx` `.pdf` `.png` 等）は base64 にして `base64Content` に渡す
  ```bash
  base64 -i "<ファイルパス>"
  ```
- **`disableConversionToGoogleType` は指定しない。** 本人の選択により Google形式に変換する
  （`.xlsx`→スプレッドシート、`.md`/`.txt`→Googleドキュメント）。
  名前の拡張子は元のまま残るので、名前と実体が一致しなくなるのは想定どおり

### Step 6: 結果を報告

`create_file` のレスポンスが返す `title` と `viewUrl` をそのまま出す。
自分で組んだ想定の名前ではなく、**APIが返した実際の名前**を報告すること。

## モード2: 既存ファイルの命名是正（`--fix`）

`$ARGUMENTS` が `--fix` で始まる場合。

### Step 1: 対象を全件列挙

`search_files` でフォルダ配下（`parentId = '<ID>'`）または検索語で列挙する。

**必ず `nextPageToken` を使って最後まで辿ること。** `pageSize` は指定しても
5〜10件程度しか返らないことがあり、1回の呼び出しで全件揃ったと思い込むと取りこぼす。
ページ境界で最後の1件が次ページの先頭に**重複して現れる**ので、fileId で重複排除する。

### Step 2: 規則から外れているものを判定

各ファイルについて:
- タイトルが `[資料名][年][月日]` 形式か（枝番 `_2` は可）
- `createdTime` を**JSTに換算**して、名前の日付と一致しているか

```bash
python3 -c "
from datetime import datetime, timezone, timedelta
t = datetime.fromisoformat('2026-08-14T22:19:48.888Z'.replace('Z','+00:00'))
print(t.astimezone(timezone(timedelta(hours=9))).strftime('%Y %m%d'))
"
```

同じJST日付のファイルが複数あれば、`createdTime` の**古い順**に無印→`_2`→`_3` を振る。

### Step 3: 変更一覧を出して確認を取る

件数が多い場合は全行ではなく「最新・最古・件数・日付の連続性・例外」に要約してよいが、
**枝番が必要なもの・日付が重複するもの・想定外の形式のものは必ず個別に挙げる**。

「これで実行していい？」と聞き、OKが出るまでリネームしない。

### Step 4: 一括リネーム

`mcp__claude_ai_Google_Drive__update_file` に `fileId` と `title` を渡す。
依存関係が無いので**1メッセージに10件ずつ並列**で投げると速い。

### Step 5: 検証

**`search_files` の `title = '<旧名>'` は完全一致にならない**（リネーム済みのファイルもヒットする）。
これで「旧名ゼロ件」を確認したことにはできない。

代わりに、各 `update_file` のレスポンスが返す `title` を1件ずつ確認する。
列挙した件数と、成功したリネームの件数が一致することをもって完了とする。
一致しなければ、どれが漏れたかを名指しで報告する。

## このスキルの制約（勘違いしやすい点）

- `update_file` で変更できるのは **`title` と `parentId` だけ**。
  既存ファイルの**中身は書き換えられない**（部分編集APIが無い）。
  中身を直したい場合は「新規作成 → 旧ファイルをゴミ箱」の置換方式になる
- 同じ資料でも mimeType が混在しうる（Googleドキュメント と 実体 `.md` の `text/plain`）。
  どちらも `update_file` でのリネームは同じように効く
- クラウドルーティンが生成するファイルは、このスキルとは無関係に
  ルーティン側のプロンプトが決めた名前で保存される。
  毎日増え続けるものを根本的に直すなら、https://claude.ai/code/routines でルーティン側を修正する
