0 2 ｜クラウド・A W S 利用状況
AWS 利用に関する考え方｜戦略的ロックイン
当社は様々なクラウドを利用しているが、スクラッチ開発の領域は「大きな波に乗る」という考え方で
AWS に集約。これを戦略的ロックインと呼んでいる。AWS を利用する理由は以下の通り。
01
AWS Well-Architected Framework に沿った構成
SoE/SoI はもちろん、重要度の高いSoR もAWS に移行。AWS Well-Architected Framework に沿った構成に
していくことでクラウド利用のメリットを享受できる。そのため、極力AWSのマネージドサービスを
活用する基本方針。
02
ユーザーの声が製品に反映される
Amazon Aurora のExtended Support 実現/ Amazon Q Developer ・AWS Incident Detection and Response の
日本語化/ Amazon Bedrock Knowledge Bases のEmbedding モデル柔軟選択など、当社の声を実際に
サービスに反映してくれた実績。
03
AI 駆動開発でも「共創」が成立する
様々なサービスの追加・レベルアップはもちろん、開発手法そのものを一緒に作り上げてくれるパートナー。

・Excel 方眼紙や図表主体の設計書など、LLM が構造を正確
に読み取りにくい既存資産が大量に存在。
・当社固有の環境・技術制約の理解。
・コンテキストウィンドウの限界。
人材・スキル
・オープン系の一般スキル不足でAI 提案を判断しきれない
場面あり。
・AI-DLC マスター（牽引人材）が社内にいない。
・新しいプロセスへの関係者の理解。

最大の課題── 「問い」のスピードに人が追いつく
AI は問いを量産し、人は問いに対してチームで議論し検証し決める。この「問い→ 検証→ 判断」の回転数が劇
的に上がることが、AI 駆動開発で最も大きな課題。
これは開発者側だけでなく、ビジネスオーナー側にも同様に求められる。
システム開発者側
・AI が大量の設計・実装案を高速に提示。
・技術的な判断を短時間で下す力が必要。
・レビューの回転スピードが開発全体のボトルネックにな
りうる。
・スキル向上とプロセス改善で対応。
ビジネスオーナー側
・AI からの要件確認・仕様判断が高頻度で発生。
・「待ち」「持ち帰り」の姿勢ではAI のスピードを活かせない。
・意識改革とスキル向上が不可欠。
・業務知識の言語化と迅速な意思決定が鍵。
AI 駆動開発の成功には、開発者とビジネスオーナー双方の意識改革とスキル向上が不可欠
― 特にビジネスオーナー側の変革が最も大きなチャレンジ
