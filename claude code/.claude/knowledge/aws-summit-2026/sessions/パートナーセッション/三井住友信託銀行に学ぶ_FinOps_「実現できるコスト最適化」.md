今後の展望
AWS CFMフレームワーク（FinOps）の導入と実践
ここまで、クイックウィンに関する話題を中心に取り上げました。ここからは、「燃えにくい建物にし、火事を起こさない意識を住人（利用者）に持
たせる」FinOpsの実践部分に話題を移します。
FinOpsとは、「みんなでコスト意識を持ち、ビジネス価値を最大化するという目標・文化」であり、AWS CFMは、「FinOpsをAWSで実現する
ための具体的な手段やテクニックを４つの柱（可視化/最適化/計画・予測/運用・実践）に整理したフレームワーク」です。
FinOps成熟度は、FinOpsと取り組みが会社組織としてどれくらいパワーアップしているのかを測るための3段階の指標で、赤ちゃんが成長
する過程に例えて評価をします。
See（可視化）：誰が、どこで、いくら使っているのか
を可視化する
Save（最適化）：無駄なリソースを停止、削除したり、
長期割引プランを活用し、コストを削減する
Plan（計画・予測）：過去のデータをもとに今後の利
用額を予測し、正しい予算を立てる
Run（運用・実践）：これらを継続的に行うためのルー
ルや担当者の責任（RACI）を決め、運用体制をつくる
Crawl（初期レベル：ハイハイ）
とりあえずクラウドを使い始めた段階。コストの集計
は手作業で、「どこで無駄が発生しているか」見えづら
い状態
Walk（中級レベル：歩き）
コストの予測や予算管理ができるようになってきた
段階。各部門が「自分たちのシステムのコスト」を意識
し始め、無駄を省く自動化なども少しずつ進んでいま
す。
Run（成熟レベル：走り） 
コストとビジネスの利益が直結して考えられている理
想の段階。高度に自動化され、全社に「コスト最適化」
の文化が完全に定着し、息をするように効率的な運
用ができています。

## p.30

29
今後の展望
 カスタムダッシュボードの全社展開
    Amazon Quickを利用し、専用のコストダッシュボードを構築し、様々なステークホルダーにレポートを提供する
ことで、組織全体にコスト意識を浸透させる。
 Amazon Managed Grafanaの全社展開
    現状、クラウド基盤担当のみで利用しているAmazon Managed Grafanaを各利用システムへ開放する事で、
    各システム担当が、リソース利用状況を視覚的に確認できるようにし、リソース最適化へ活用してもらう。
余剰リソースチェックや各種割引プランの活用など、既に対応している内容に対しては以下の様な改善を行い、より高い効果を狙う。
 Reserved Instanceの適用範囲拡大
    Amazon RDSへ適用するRIについては、適用対象の選定不備による余剰コスト発生のリスクを回避する為、
    適用するDBエンジンを絞っているが、本条件を見直し適用範囲を拡大する。
AWS CFMフレームワーク（FinOps）の導入と実践
当社のコスト最適化運用は、FinOps成熟度「Crawl（初期）～Walk（中級）レベル」に位置している。
可視化・契約・自動化の技術的要素は比較的高い成熟度を示しているが、予実管理・責任分担の制度化が未整備である。
今後は、AWSコストをシステム単位での負担に転換し、各システム単位でコスト計画と実績を可視化・管理することが重要と
考える。また、FinOps定例会やRACIを整備しながら、コスト最適化に関する運用体制を確立する事で、システム投資のビジ
ネス価値を高める活動の土台を構築することも重要なポイントとなると思料する。
