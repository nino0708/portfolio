# タスクの着手期間とスロットピッカー

## 背景・課題

今日の時間割にタスクを配置する手段が、ドラッグ&ドロップしかない。タスク一覧とタイムラインの間の距離が離れているレイアウトでは、ドラッグ操作が届かず配置できない場合がある。

代替として「ボタンを押すと今日の空き時間の候補が出て、選ぶだけで配置できる」導線を追加する。あわせて、タスクに「いつからいつまでに終わらせるか」という期間を持たせ、週次・月次ビューでその期間を俯瞰できるようにする。これにより、今日のスケジュールを組む時に「週次・月次で見えているタスクのうち、今日どれをやるか」を判断してから配置する、という流れにする。

## スコープ

- `Task` に着手可能日フィールドを追加する
- 期間（着手可能日〜期限）を入力する軽量UIを追加する
- 週次・月次ビューに期間を表示する
- タスク一覧の行に「候補」ボタンを追加し、今日の空き時間候補から選んで配置できるようにする

スコープ外：
- 複数日にまたがる時間ブロックの一括配置（ユーザーの申告により別対応）
- 期間の視覚的な連結バー表示（セル単位のチップ表示で十分とする。YAGNI）
- 候補提示の対象日を今日以外に広げること（今回は今日固定）

## ① データモデル

`src/types/domain.ts` の `Task` に追加:

```ts
windowStart: string | null;  // 'YYYY-MM-DD'。着手可能日。null = 未設定
```

- 既存の `dueAt`（終わらせる期限）はそのまま。期間＝`windowStart 〜 dueAt`。
- `windowStart` のみ設定・`dueAt` のみ設定・両方未設定、すべて許容する（必須項目はタイトルだけという既存方針を崩さない）。

Supabaseマイグレーション: `tasks` テーブルに `window_start date null` を追加。

`src/lib/tasks.ts`:
- `mapRow`（行→`Task`変換、行16付近）に `windowStart: (r.window_start as string) ?? null` を追加。
- `updateTask` の呼び出し元から `{ window_start }` を渡せるようにする（既存の `updateTask(id, patch)` はSupabaseの `update` にそのまま渡すジェネリックな形なので、呼び出し側でスネークケースのキーを渡せば追加実装は不要）。

## ② 期間の入力UI

`src/components/TaskDetail.tsx` の `detail-meta` 行に「期間」バッジを追加する。

- 表示: 期間が設定されていれば `期間 8/25〜8/31`、未設定なら `期間未設定`。
- 押すと、既存の見積もりバッジ（`TaskList.tsx` 行99-103）と同じ `window.prompt()` の流儀で:
  1. `着手可能日（YYYY-MM-DD、空欄で解除）` を聞く
  2. `期限日（YYYY-MM-DD、空欄で解除）` を聞く
- 期限日は既存の `dueAt`（ISO日時）に書き込む際、時刻部分は現地時刻23:59を補う（日単位の入力のため）。
- 新規モーダル・新規ダイアログコンポーネントは作らない。

## ③ 週次・月次ビューへの反映

`src/components/CalendarView.tsx`:

- 新しいitem種別 `'window'` を追加。
- `windowStart` が設定されているタスクについて、`windowStart〜dueAt`（`dueAt`未設定なら`windowStart`のみ1日）の範囲に含まれる各日に、そのタスクのchipを表示する。
- 既存の `dueItems`（点表示の期限マーカー、行40-44）とは別に `windowItems` を作り、`items` 配列に合流させる。
- 見た目は既存の `.cal-item` に `window` 用のCSSクラス（破線ボーダー等、既存の `due`/`task`/`event` と区別できる見た目）を追加。
- 月表示の「+N件」省略ロジック（行98-100）はそのまま流用し、追加実装しない。

## ④ 候補スロットボタン

`src/components/TaskList.tsx` の行に、ドラッグハンドル（`⠿`）とは別に「候補」ボタンを追加する。

- 表示条件: `windowStart` が未設定、または `windowStart <= today <= (dueAt ?? today以降)` の時のみ表示（期間が今日を含まないタスクには出さない）。
- 押すと行の下に候補パネルが開く（`opened` と同じ仕組みの別state、`TaskDetail`の開閉とは独立させる）。
- 候補パネルの中身:
  - 今日のカレンダー予定（`CalendarEvent`）と既に確定済みの `scheduledStart/End` を busy として、`src/lib/plan.ts` の `subtractBusy` を使い今日の空きギャップを算出。
  - `estimateMin` に収まるギャップから、先頭2〜4件を候補として提示（各ギャップの先頭時刻を候補開始時刻とする。1ギャップが長い場合の複数候補分割はしない＝YAGNI）。
  - 候補が0件の場合は「今日は空きがない」と表示する。
- 候補ボタンを押すと、ドラッグ&ドロップ配置と同じ処理（`App.tsx` の `scheduleTask` 相当、`updateTask(id, { scheduled_start, scheduled_end })` → `reload()`）を呼ぶ。新しいSupabase呼び出しは不要、既存の `scheduleTask` をそのまま再利用する。

## テスト方針

- `src/lib/plan.ts` の空きギャップ抽出は既存関数の再利用のため新規ユニットテストは最小限（候補選定のトップN切り出し部分のみ追加）。
- UIの動作確認は `/app-glow-up` の検証手順に準じ、ヘッドレスChromeでスクリーンショットを撮って目視確認する。
