# new-skill — スキルを作るスキル

Claude Code公式ドキュメントのベストプラクティスに基づいて、正しい構造・配置・フロントマターを持つスキルファイルを生成します。

## 使い方

```
/new-skill
/new-skill デプロイ手順を実行するスキル
/new-skill コードレビューチェックリスト（リファレンス型）
```

## 実行手順

### Step 1: 情報収集

$ARGUMENTS が空の場合は AskUserQuestion で以下を確認する。$ARGUMENTS がある場合はそこから読み取って補完する。

**確認事項：**

1. **スキル名**（英数字・ハイフンのみ）
   例: `deploy`, `review-pr`, `api-style-guide`

2. **スキルの説明**（1行、Claude がいつ使うかを判断するために使われる）
   例: "ステージング環境へのデプロイ手順を実行する"

3. **スキルの種類** — 以下から選ぶ：
   - **ワークフロー型**: Claudeに特定の手順を実行させる（`/deploy` のように呼び出す）
   - **リファレンス型**: ドキュメント・スタイルガイド等（Claudeが必要時に自動ロード）

4. **副作用があるか**（外部への送信・コミット・デプロイ・ファイル削除等）
   → YES の場合は `disable-model-invocation: true` を設定（明示的に呼ぶまでコンテキストに入らない）

5. **$ARGUMENTS を使うか**（呼び出し時に引数を受け取るか）
   例: `/fix-issue 1234` → `$ARGUMENTS` = "1234"

6. **パス制限があるか**（特定のファイル種別・ディレクトリにのみ適用）
   → YES の場合は `.claude/rules/` に配置してパス frontmatter を設定

### Step 2: ベストプラクティスの適用判断

以下の判断を行い、ユーザーに確認してから進める：

```
■ 配置場所の決定
  - ワークフロー型 → .claude/commands/<name>.md
  - リファレンス型（全体） → .claude/commands/<name>.md
  - リファレンス型（パス限定） → .claude/rules/<name>.md（paths: frontmatter付き）

■ disable-model-invocation の判断
  副作用あり（コミット・デプロイ・外部送信・削除等） → true に設定
  副作用なし（調査・生成・レビュー等） → 省略（デフォルトでClaudeが自動判断）

■ コンテキストコストの考慮
  スキル説明はセッション開始時に毎回ロードされる（~数十トークン）
  スキル本文は呼び出し時のみロード
  → 説明は簡潔に（1〜2文）、本文に詳細を書く
```

### Step 3: スキルファイルの生成

以下のテンプレートに情報を埋め込んでファイルを生成する。

**ワークフロー型（副作用なし）：**
```markdown
---
name: <スキル名>
description: <1〜2文の説明。Claudeがいつ使うか判断する基準になる>
---

# <スキル名> — <人間向けタイトル>

<このスキルが何をするか、なぜ使うかを1〜2文で>

## 使い方
\`\`\`
/<スキル名>
/<スキル名> <引数の例>（引数を受け取る場合）
\`\`\`

## 手順

$ARGUMENTS を受け取る場合: $ARGUMENTS に基づいて処理する。

### Step 1: <最初のステップ>
<具体的な指示>

### Step 2: <次のステップ>
<具体的な指示>

（以降、必要なステップを追加）
```

**ワークフロー型（副作用あり）：**
```markdown
---
name: <スキル名>
description: <1〜2文の説明>
disable-model-invocation: true
---

# <スキル名>

⚠️ このスキルは副作用があります（<何をするか>）。明示的に /<スキル名> で呼び出した場合のみ実行されます。

## 実行内容
<何をするか箇条書き>

## 手順

### Step 1: 確認
<実行前に確認すべき事項>

### Step 2: 実行
<具体的な手順>

### Step 3: 検証
<実行後の確認方法>
```

**リファレンス型：**
```markdown
---
name: <スキル名>
description: <1〜2文。"〜に関するリファレンス"のように書く>
---

# <タイトル>

## 概要
<ドキュメントの目的・スコープ>

## <セクション1>
<内容>

## <セクション2>
<内容>

（以降、リファレンス内容を記述）
```

**パス限定リファレンス型（`.claude/rules/` に配置）：**
```markdown
---
paths:
  - "<glob パターン>"
---

# <タイトル>

<このパターンのファイルに適用されるルール・規約>
```

### Step 4: ファイル作成

決定した配置場所にファイルを作成する。

```bash
# 確認
cat <作成したファイルのパス>
```

### Step 5: 動作確認と案内

作成後に以下を伝える：

1. **呼び出し方法**
   - ワークフロー型: `/<スキル名>` または `/<スキル名> <引数>`
   - リファレンス型: Claudeが自動判断するか、`/<スキル名>` で明示的に読み込み
   - パス限定型: 該当ファイルを操作するときに自動ロード

2. **コンテキストコストの説明**
   - `disable-model-invocation: true` の場合: 呼び出すまでコンテキストへの影響ゼロ
   - 通常の場合: スキル説明がセッション開始時にロードされる

3. **改善のヒント**（必要に応じて）
   - スキルが長すぎる場合は分割を提案
   - 頻繁に使うなら CLAUDE.md への追記も提案

## ベストプラクティス早見表（このスキル自身の参照用）

| 状況 | 対応 |
|---|---|
| コミット・デプロイ・外部送信する | `disable-model-invocation: true` |
| 特定ファイル種別にのみ適用 | `.claude/rules/` + `paths:` frontmatter |
| 調査・探索が多いスキル | スキル内でサブエージェント使用を指示 |
| スキルが長くなりすぎる | 複数スキルに分割 |
| 常に覚えておくべきルール | CLAUDE.md へ（スキルではなく） |
| プロジェクト横断で使いたい | `~/.claude/commands/` に配置 |
