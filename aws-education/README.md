# aws-education

AWSの後進育成について、相談しながら方針を決めたり、教材や発信記事を作ったりする場所。

## 対象とゴール

- **対象**：会社の後輩と、これからAWSを学び始める先輩
- **ゴール（いまのKPI）**：情報発信の回数。育成した人数ではない → [`publications.md`](publications.md) で数える
- **使える時間**：資料作りに月10時間くらい

## 発信シリーズ

| フォルダ | シリーズ | 中身 | 頻度（案） |
|---|---|---|---|
| [`monthly-aws/`](monthly-aws/) | 月刊AWS | AWSを楽しく始めるための初歩的な情報を発信するブログ（[ネタ帳](monthly-aws/ネタ帳.md)） | 月1本 |
| [`build-tasks/`](build-tasks/) | AWS事前構築課題 | 簡単な構築課題を出して、手を動かして学んでもらう（[予定](build-tasks/予定.md)） | 月1本（問題と回答を1ヶ月ずつ交互に） |
| [`info-share/`](info-share/) | AWS情報共有 | 資格試験のお得な情報や、AWSで最近あったことの共有 | 不定期（発信回数には入れない） |

## 発信のペース

| 内容 | 頻度 | 発信回数/月 |
|---|---|---|
| 月刊AWS | 毎月 | 1 |
| 構築課題 | 毎月（偶数月に問題、奇数月に回答） | 1 |
| ネタ集め | 3ヶ月に1回（12月・3月・6月・9月） | - |
| **合計** | | **2回** |

使える時間は月10時間くらい。月刊AWSと、問題を出す月の構築課題はテーマをそろえて準備を使い回す。

## 育成の方針

- **ハンズオン → 検証 → 資格** の順で学ぶ。資格は後からついてくる
- 運用・保守の現場で使える力を優先する（監視、障害対応、変更管理、コスト）
- 作業は手順書にまとめ、IaC（Terraform）で再現できる形にする
- 障害対応は「異常検知 → 切り分け → 報告 → 復旧 → ポストモーテム」の型で身につける
- ダブルチェックと記録管理を徹底する（航空整備の現場で学んだ考え方を持ち込む）
