# aws-education

AWSの後進育成について、相談しながら方針を決めたり、教材や発信記事を作ったりする場所。

## 対象とゴール

- **対象**：会社の後輩と、これからAWSを学び始める先輩
- **ゴール（いまのKPI）**：情報発信の回数。育成した人数ではない → [`publications.md`](publications.md) で数える
- **使える時間**：資料作りに週10時間くらい

## 発信シリーズ

| フォルダ | シリーズ | 中身 | 頻度（案） |
|---|---|---|---|
| [`monthly-aws/`](monthly-aws/) | 月刊AWS | AWSを楽しく始めるための初歩的な情報を発信するブログ | 月1本 |
| [`info-share/`](info-share/) | AWS情報共有 | 資格試験のお得な情報や、AWSで最近あったことの共有 | 週1本 |
| [`build-tasks/`](build-tasks/) | AWS事前構築課題 | 簡単な構築課題を出して、手を動かして学んでもらう | 月2本 |

## 週10時間の配分（案）

月40時間として、次のように使う。

| 内容 | 時間/月 | 発信回数/月 |
|---|---|---|
| 月刊AWS 1本 | 8h | 1 |
| AWS情報共有 週1本 | 6h（1.5h × 4） | 4 |
| 構築課題 2本（検証を含む） | 16h（8h × 2） | 2 |
| 振り返り・相談・ネタ集め | 10h | - |
| **合計** | **40h** | **7回** |

## 育成の方針

- **ハンズオン → 検証 → 資格** の順で学ぶ。資格は後からついてくる
- 運用・保守の現場で使える力を優先する（監視、障害対応、変更管理、コスト）
- 作業は手順書にまとめ、IaC（Terraform）で再現できる形にする
- 障害対応は「異常検知 → 切り分け → 報告 → 復旧 → ポストモーテム」の型で身につける
- ダブルチェックと記録管理を徹底する（航空整備の現場で学んだ考え方を持ち込む）
