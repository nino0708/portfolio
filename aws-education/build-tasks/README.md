# AWS事前構築課題

育成対象の人に簡単な構築課題を出して、手を動かして学んでもらう。

- **ファイル名**：`NN_テーマ.md`（例：`01_S3静的サイト.md`）
- 出す順番は [`../curriculum/roadmap.md`](../curriculum/roadmap.md) のフェーズに合わせる
- 公開する前に、自分で最後まで手順どおりに構築して確認する（ダブルチェック）

## 課題テンプレート

```markdown
# 課題NN：〇〇

- 難易度：★☆☆
- 目安時間：〇時間
- 想定コスト：〇円（無料利用枠内なら明記）
- 対応フェーズ：〇

## ゴール（完成したらこうなる）
（構成図も貼る）

## 条件
- 

## ヒント
（答えは書かない。調べるキーワードを書く）

## 確認方法
（ちゃんとできたかを本人が確認する方法）

## 片付け
（課金を止めるために消すリソースの一覧）

## 振り返り
- 詰まったところ：
- 学んだこと：
```

## 実際のExcelの形式（5,6月・7,8月で使っているもの）

1つのブックに「課題」と「解答」のシートを並べる（例：`5,6月課題` / `5,6月解答` / `7,8月の課題`）。

### 課題シート
- B列にタイトル（「7,8月の課題」）
- G列に **目標**（「ブラウザから〇〇にアクセスしたときに、〇〇の index.html が表示される」の形）
- **~要件~**：リージョン、EC2（AMI・インスタンスタイプ・パブリックIPの有無）など、指定するものだけ書く
- ユーザーデータ（httpd を入れて `Hello World!!<作成した日付>` を表示するスクリプト）をそのまま貼る
- 左側に構成図（draw.io で作成。「※必要なサービスや設定が全て書かれているとは限りません」と注記）
- 最後に本人が書く欄：「理解できたこと」「解決できなかったこと」「面談で相談したいこと」

### 解答シート
- B列（幅60）に説明文、C列より右にコンソールのスクショを貼る（スクショ自体には書き込まない）
- 見出しは2段：「セクションN 〇〇」＞「N－M 〇〇」（太字、B:Jを結合）
- 各項目の最初に、そのサービスのアイコン（構成図から切り出したもの）と、1行の用語説明（「〇〇：〜するもの」）
- 手順は「〇〇を選択→」のように、右のスクショのどこを見るかを → で指す。要件で決まっている値は「要件である〜」と書く
- 必要な所だけ赤枠（四角・線の図形）で強調
- 流れ：ネットワーク（VPC → サブネット → IGW → ルートテーブル）→ サーバー（EC2 → 動作確認）→ 課金対象リソースの削除 → 補足（キーペア・SSHで入って設定を確認 など）
